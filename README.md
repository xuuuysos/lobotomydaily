# Lobotomy Daily — Новостной Агрегатор

Интеллектуальный новостной агрегатор на Django с поддержкой автоматической категоризации новостей с помощью искусственного интеллекта (OpenRouter / Gemini) и гибкой системой фильтрации.

---

## 🛠 Техническая архитектура и компоненты

### 1. Модели базы данных (ORM)
Система работает на базе 4 основных сущностей:
* **`News`** — Хранит информацию о спарсенных публикациях: заголовок (title), источник (source), URL (url), текст новости (body) и дату публикации/парсинга (parsed_at).
* **`NewsAITags`** — Кэш-таблица для хранения сгенерированных ИИ тегов в формате JSON по уникальному URL новости. Это позволяет избежать повторных запросов к API нейросети.
* **`Comment`** — Комментарии пользователей к статьям, привязанные к модели `User` и URL новости.
* **`Bookmark`** — Сохраненные пользователем публикации (закладки), связывающие `User` и URL новости.

## 🔌 Как добавить новый источник новостей

Парсер новостей реализован в виде Django-команды в файле [parse_news.py](file:///d:/lobotom/lobotomynews/core/management/commands/parse_news.py).

Чтобы добавить новый источник (например, `Meduza` или `RBC`):
1. **Напишите метод получения ссылок**:
   Добавьте в класс `Command` метод `get_newsource_links(self, date_obj)`:
   ```python
   def get_newsource_links(self, date_obj):
       url = f"https://newsource.com/archive/{date_obj.strftime('%Y/%m/%d')}/"
       html = self.fetch_html(url)
       soup = BeautifulSoup(html, 'lxml')
       links = []
       for a in soup.find_all('a', href=True):
           # Логика извлечения ссылок, заголовков и времени
           links.append({
               'url': a['href'],
               'title': a.get_text(),
               'source': 'NewSource',
               'pub_time': timezone.now()
           })
       return links
   ```
2. **Интегрируйте метод в диспетчер**:
   Внутри метода `fetch_links_for_day` вызовите ваш новый метод, обернув его в блок `try-except` для обеспечения отказоустойчивости:
   ```python
   newsource = []
   try:
       newsource = self.get_newsource_links(target_date)
   except Exception as e:
       self.stdout.write(self.style.ERROR(f"Error parsing NewSource: {e}"))
   ```
3. **Добавьте результаты в общий список**:
   Вставьте извлеченные ссылки в итоговый массив `day_links` для последующей параллельной обработки через ИИ.

## 🔍 Как устроены фильтры

### 1. Фильтрация по датам
Пользователь может выбрать временной диапазон "ОТ" и "ДО" на боковой панели.
* Логика обрабатывается во view-функции `index` в [views.py](file:///d:/lobotom/lobotomynews/core/views.py).
* Запрос принимает параметры `from` и `to` (формат `YYYY-MM-DD`).
* Для предотвращения перегрузки БД диапазон дат **ограничен максимум 14 днями** (каппинг выполняется автоматически на стороне бэкенда).

### 2. Фильтрация по тегам (Категории)
Пользователь может включать (символ `+`) или исключать (символ `-`) определенные теги на панели тем.
* API эндпоинт `/api/category-news/` принимает массивы `includedTags`, `excludedTags` и `dates`.
* Для каждого дня в диапазоне запускается метод `_parse_lenta_day_filtered`.
* Фильтрация происходит с помощью сравнения множеств (Set Operations):
  ```python
  # include_set — теги, которые должны присутствовать (ИЛИ)
  # exclude_set — теги, которых быть не должно
  matches_include = not include_set or not include_set.isdisjoint(tags_set)
  matches_exclude = not exclude_set or exclude_set.isdisjoint(tags_set)
  ```
* Если новость удовлетворяет обоим условиям, она попадает в выдачу.

## 🛡️ Безопасность и надежность данных

1. **Изоляция сбоев**: Ошибки парсинга или недоступности одного из сайтов (Lenta.ru, RIA.ru, Fontanka.ru) изолированы благодаря блокам `try-except` на каждый источник. Падение одного сайта не прерывает работу парсера для остальных.
2. **Повторные попытки (Retries)**: Функция `fetch_html` делает до **3 попыток подключения** с интервалом в 1 секунду в случае сетевого сбоя или таймаута перед тем, как зафиксировать ошибку.
3. **Асинхронность**: Парсер запускается в отдельном daemon-потоке (`threading.Thread`) при старте приложения, что полностью освобождает основные рабочие процессы Django от блокировок. Статус обновления выводится на боковую панель.
4. **Валидация URL**: Все входящие ссылки в API эндпоинтах проверяются с помощью валидатора `URLValidator()`. Запросы с некорректным URL отсекаются с кодом ответа `400 Bad Request`.
5. **Санитизация контента**: Комментарии пользователей перед сохранением проходят через функцию `strip_tags()`, которая вырезает любые HTML-теги (например, `<script>`, `<iframe>`), предотвращая XSS-атаки.

## 📄 Генерация документации кода

В проекте настроена автоматическая генерация технической HTML-документации на основе docstring-комментариев кода с помощью генератора **pdoc**.

### 1. Локальная генерация
Для локальной сборки документации выполните:
```bash
# 1. Установите зависимости проекта
pip install -r requirements.txt

# 2. Сгенерируйте HTML-документацию
$env:DJANGO_SETTINGS_MODULE="init.settings"
pdoc --output-directory docs core
```
После этого интерактивная документация будет доступна в каталоге `docs/index.html`.

### 2. Автоматическая сборка в CI/CD
В файле `.gitlab-ci.yml` настроен шаг `docs-job`, который:
* Автоматически запускается в GitLab CI/CD пайплайне на этапе `docs`.
* Генерирует актуальную HTML-документацию проекта.
* Сохраняет ее в артефактах сборки GitLab на 1 неделю (каталог `docs/`).
